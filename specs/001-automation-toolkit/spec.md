# pr-sync — Specification

## Purpose
pr-sync is a CLI tool that creates or updates a single GitHub pull request (PR) for the current git branch, based on the diff against a base branch.
It ensures that:
- there is at most one open PR per (base, head) pair, and
- the PR body follows a standard structure, suitable for further processing by docs-assistant and release tooling.

## Inputs
- **Environment**:
  - Must run inside a git repository.
  - `git` and `gh` must be available in PATH.
  - GitHub authentication is handled by `gh` (gh auth login or tokens).
- **Git**:
  - Current branch: resolved via `git rev-parse --abbrev-ref HEAD`.
  - Base branch: CLI option `--base` (default `develop`).
  - Diff and commits between base and current branches.
- **CLI options (high-level)**:
  - `--base <branch>`: base branch, default `develop`.
  - `--title <string>`: explicit PR title (optional).
  - Optional overrides for PR body sections MAY be added later (e.g. risks/config/testing/notes) and will be specified in the full spec.

## Outputs
- **Exit codes (high-level categories)**:
  - `0` — success: PR created or updated.
  - `1` — expected non-fatal failure: no diff, ambiguous PR state, invalid usage.
  - `2` — environment/auth failure: no git/gh, not a git repo, or gh not authenticated.
- **Side effects**:
  - If a single matching open PR exists, its title and body are updated.
  - If no matching PR exists, a new PR is created with the generated title/body.
  - If multiple matching PRs exist, no PR is modified or created.
- **User-visible output**:
  - On success: prints PR number and URL.
  - On failure: prints a human-readable reason to stderr.

## PR body structure
The PR body generated by pr-sync MUST include the following sections, each with non-empty content:
- `## Summary`: describes intent and mentions base and current branch.
- `## Changes`: lists changed files.
- `## Commits`: shows commits between base and current.
- `## Risks`: standard template or overrides, never empty.
- `## Config`: standard template or overrides, never empty.
- `## Testing`: standard template or overrides, never empty.
- `## Notes`: standard template or overrides, never empty.

A timestamp marker (e.g. `_Last updated by pr-sync at 2026-08-05 22:34:12 +03:00._`) MAY be included, typically in the Notes section.

## Key Invariants
- **Single PR per (base, head)**: Never create a second open PR when one already exists for the same base and head.
- **No PR actions on empty diff**: If there are no changes between base and current branches, do not create or update any PR.
- **Non-empty sections**: All body sections listed above must be present and non-empty.
- **Idempotency (up to timestamp)**: Running pr-sync twice in a row with the same inputs and no new commits must produce the same PR body, except for an optional timestamp.
- **Safe behavior without auth**: If `gh` is missing or not authenticated, pr-sync must not attempt PR operations and must exit with a clear error.
