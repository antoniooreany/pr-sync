# SDD Phase 2: Analyze & Retrospective

## 1. Анализ инвариантов
- **Single PR per base/head:** Реализовано через `gh_api.find_open_pr()`.
- **No PR actions on empty diff:** Реализовано и защищено в `invariants.check_no_empty_diff_action()`. Exit-код обрабатывается в `cli.py`.
- **Safe behavior without auth:** Функция `gh_api.check_auth()` корректно возвращает код 2 при отсутствии аутентификации.

## 2. Ретроспектива (Уроки и Риски LLM)
Разработка `pr-sync` показала, что базовая автоматизация (MVP v1.0.0) собирается быстро и решает основную проблему. Однако, попытка интегрировать LLM для генерации текста вскрыла существенные риски:
- **Перерасход ресурсов:** LLM-слой требует сложной обработки ошибок (fallback), тестирования промптов и кэширования.
- **Нарушение идемпотентности:** LLM по своей природе недетерминирована.
**Решение:** Версия v1.0.0 выпущена без LLM. Любые интеграции ИИ (v1.1+) должны разрабатываться в изолированных ветках и не блокировать работу MVP.

## 3. Оркестрация ИИ-агентов
- Агенты должны работать строго по правилам Gitflow (один агент = одна feature ветка).
- Запрещено прямое внесение изменений в `main`/`develop` без PR.
